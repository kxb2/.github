## 1. 목적 / 한 줄 정의

> **Objective (검증 목표)**
시나리오·장르·레퍼런스 이미지(선택) 입력만으로 9컷 스토리보드와 통합 영문 프롬프트를 자동 생성하고, 그 산출물이 영상 제작 AI의 입력 규격을 충족하는지 검증한다.
> **Hypothesis (검증 가능한 가설)**
> 장르 프리셋과 자동 프롬프트 조립을 제공하면, 프롬프트에 미숙한 일반 사용자도 별도 학습 없이 영상 제작 AI 투입 가능 수준의 스토리보드·프롬프트를 한 번에 생성한다.

### 핵심 정의

- 기획(텍스트)과 영상화 사이의 스토리보드 단계 자동화
- 입력 — 시나리오 프롬프트(최대 500자) + 장르 + (선택) 레퍼런스 이미지
- 출력 — **그리드 이미지 1장** + 통합 영문 프롬프트 1블록 → 영상 AI 전달
- **단위 = 이미지 1장** — 컷 개별 생성·합성 없음. 생성·화면 표시·내보내기 전 구간에서 그리드 이미지 1장을 단일 단위로 취급
    - 단, 내부적으로는 격자선 탐지 후 **컷 9장으로 크롭·저장**하며, 이미지 Export의 ‘개별 컷 포함’ 옵션에서만 사용자에게 노출된다(§5 F-06)
- 레퍼런스 이미지 = 선택 입력
    - 미첨부 시 시나리오 텍스트만으로 생성
    - 첨부 시 최대 10장(0~10장) · 로컬 수동 업로드 · 긴 변 1024px로 축소 후 저장(Claude 입력 토큰 절감)
    - **수신 주체는 Claude API** — 이미지 모델에 직접 투입되지 않음(§5 F-02)

### 전체 흐름상 위치

기획(텍스트) → **[B] 그리드 이미지 1장 → 통합 프롬프트** → 영상 AI(첫 프레임 정밀 생성 → 15초 영상화) → 합치기 → 음악·자막

### 제품 컨셉

- “전문가(방송 PD)가 만든, 누구나 쉬운 도구”
- 실사용 타깃 10~80대 · 기준 사용성 30~40대 · 접근성 최우선

> 캔버스(F-04)는 생성 파이프라인의 단계가 아닌 독립된 자유 배치 보드 — §3·§5 F-04에서 별도 정의.

## 2. 성공 기준 (데모에서 증명할 것)

### 데모 완주 기준 — **달성**

- 한국어 시나리오 1건 입력 → 그리드 이미지 1장 + 통합 영문 프롬프트 → Export까지 끊김 없이 1회 통과
- 목표 = 완성도가 아닌 파이프라인 완주
- 레퍼런스 미첨부 / 첨부 두 경로 모두 성립

### 캔버스 성공 기준 (독립·비차단) — **달성**

- 빈 보드에서 임의 이미지/영상 반입 → 자유 배치·연결·메모 가능
- 데모 완주 기준과 독립적으로 별도 성립

> **KPI·이벤트 스키마·A/B 실험 설계 = 본 범위 제외.** 지표로 가설을 통계 검증하는 실험형이 아닌, 파이프라인을 끝까지 통과시키는 데모 완주형 MVP.

## 3. User Flow

### 생성 파이프라인 (스토리보드) — 단일 흐름

입력 → 생성 → 검수·재생성 → 프롬프트 확인 → Export → 영상 AI 영상 제작

| 단계 | 사용자 행동 | 대응 기능 |
| --- | --- | --- |
| 0 | 로그인 (이메일 가입 / 구글) | F-07 |
| 1 | 시나리오 입력(≤500자) · 장르 선택 | F-01 |
| 2 | (선택) 고급 설정 조정 — 이미지 모델 · 그림체 | F-01 고급 |
| 3 | (선택) 레퍼런스 이미지 첨부(0~10장) · 생성 실행 | F-01 / F-02 |
| 4 | 그리드 이미지 1장 검수 | F-02 |
| 5 | 실패 시 안내 확인 → **[재생성]** 클릭 / 결과 불만족 시 [스토리보드 만들기] 재실행 | F-02 |
| 6 | 통합 프롬프트 · 글자수 확인 (더보기로 전문 펼침) | F-03 |
| 7 | 내보내기 — 형식 선택(PDF / 이미지) | F-05 / F-06 |
| 8 | 생성 프롬프트·이미지로 영상 AI 영상 제작 | 범위 경계 |

작업물 관리 — 스토리보드는 생성과 동시에, 캔버스는 변경 시마다 자동 저장(F-08a) · 저장분은 라이브러리 목록에서 조회·재진입하고 제목 수정·삭제로 정리한다(F-08b).

### 캔버스 (독립 기능 · 파이프라인 외)

빈 캔버스에 임의 이미지/영상 반입 → 섹션·커넥터·메모로 자유 배치·정리(F-04, 병렬·비차단).

> **다운스트림(영상 AI)** — 사용 모델 3종 = Seedance 2.0 · Kling 3.0 · Grok 1.5. 그리드 이미지 1장 + 통합 프롬프트로 15초 통짜 영상 1개 생성. 프롬프트 3000자 제약은 Seedance 2.0 기준(§9).
**A라인과 실제로 API를 맞춰본 적은 없음** — 현재는 사람이 결과물을 복사해 옮기는 방식을 전제로 설계됐다.

## 5. 기능 명세 + 수용 기준

### F-01 시나리오 입력 (P0) — 기본/고급 2단 구조

**기본 화면 (항상 노출)**

- 시나리오 텍스트박스 1개(한국어 자연어·자유 입력) · **최대 500자** · 반응형 확대 입력
- 장르 칩 1줄 — 드라마 / 액션 / 로맨스 / 스릴러 / 코미디 (5종)
- 레퍼런스 이미지 첨부 — 선택 입력 · 최대 10장 · 개별 삭제 가능
- [스토리보드 만들기] 버튼 — 생성 후에도 입력값(시나리오·장르·고급 설정·첨부 이미지) 유지 · 재실행 시 재입력 불필요

**입력 검증 규칙**

- 0장 → 생성 버튼 활성 / 1~10장 → 생성 버튼 활성 / 10장 초과 → 첨부 차단 + 안내 노출

**고급 설정 (접힘·펼침)**

- **항목 2종만** — ① 이미지 모델 선택 ② 그림체
- 이미지 모델 = 2종 · 기본값 **GPT Image 2**(`gpt-image-2`) / **Gemini 3.1**(`gemini-3.1-flash-image`)
    - **UI 표기는 **`**GPT Image 2**`** / **`**Nano Banana 2**` — 후자는 Gemini 이미지 모델의 통용 명칭이다. 발표자료·화면 문구는 이 표기를 쓰고, 환경변수·코드는 `gemini-3.1-flash-image`를 쓴다. **같은 모델의 다른 층위 표기이며 불일치가 아니다**
- 그림체 = **3종 고정 선택** — 실사(기본값) / 3D 애니메이션 / **2D 애니메이션(= 일본풍 고정)** · 자유 입력·기타 스타일 미제공
- 제외된 항목과 처리 — 톤 = 장르 프리셋 고정 · 시대 배경 = 시나리오 텍스트로 표현 · 화면비 = 3:2 고정(§7-11)
- 미조정 시 기본값 적용(GPT Image 2 + 실사) · 조정 시 오버라이드
- 원칙 — 사용자 다수는 시나리오+장르 선택만으로 완성 가능해야 함. 선택지를 늘리기보다 좋은 기본값으로 해결

> ⚠️ **미구현 (잔여 과제)** — 기획상 첨부 영역에 넣기로 한 안내 2건(① 이미지는 Claude가 분석해 프롬프트에 반영하며 외형 정확 재현이 아님 ② 실존 인물 사진은 분석 거부될 수 있음)이 **UI에 들어가지 않았다.** 현재 문구는 오히려 외형 재현을 기대하게 만드는 방향(“참고 이미지를 넣으면 퀄리티가 훨씬 좋아져요 / 캐릭터, 배경, 소품 등”)이다. **문구 추가만으로 끝나는 작업.**

> **수용 기준** — 시나리오 입력 + 장르 선택만으로 생성 버튼이 활성되고, 첨부 0장 / 1~10장 / 11장 이상 세 경우가 각각 규칙대로 동작한다.

### F-02 9컷 생성 (P0) — 단일 호출 · 그리드 이미지 1장

**생성 파이프라인 2단계**

| 단계 | 주체 | 입력 | 출력 |
| --- | --- | --- | --- |
| 1 | **Claude Sonnet 5** | 시나리오 + 레퍼런스 이미지(0~10장) + 장르 프리셋·고급 설정 | 공유라인 + Shot 1~9 영문 텍스트 |
| 2 | **이미지 모델** | 격자 기술 지시문 + 그림체 강제문 + 1단계 산출 **텍스트만** | 그리드 이미지 1장 |

- **레퍼런스 이미지는 이미지 모델로 전달되지 않는다** — Claude가 비전 분석해 프롬프트 텍스트로 변환한 결과만 전달(분석 상세 = F-03)
- 이미지 모델 입력 = 텍스트 100% · image-to-image·레퍼런스 직접 투입 미사용(§8)
- 참조 충실도 한계 — 이미지가 텍스트를 경유하므로 **외형 정확 재현은 불가** · 레퍼런스는 분위기·구도·스타일 참조 수준
- **그림체는 Claude에게 맡기지 않고 사용자가 고른 값을 백엔드가 강제**한다(2D 애니메이션 → 내부 `japanese anime`)

**생성 규칙**

- **호출 단위 — 1 스토리보드 = 이미지 모델 호출 1회** · 컷 개별 생성 후 서버 합성(스티칭) 미채택
- 격자 분할은 모델이 렌더링 — 프롬프트에 3×3 레이아웃·헤어라인 구분선 명시 강제, **패널 번호는 넣지 말 것**으로 지시
- 검수·산출 모두 이미지 1장 단위 · 화면비 3:2 고정
- 장르 앵글 아크 프리셋에 따라 9컷 샷 타입 자동 배정(프롬프트에 반영 · 컷별 수동 오버라이드 없음)
- 컷별 앵글 명시 강제 — [앵글명 + 카메라 물리 위치 + 결과 묘사] 3겹 구조 · 추상 무드어 금지

**격자선 탐지 크롭 (신규 명문화)**

생성된 그리드 1장을 컷 9장으로 쪼갤 때 **정확히 1/3·2/3 지점을 자르지 않는다** — 모델이 픽셀 단위로 균일하게 그려주지 않기 때문.

1. 흑백 변환 → 2. 1/3·2/3 지점 **주변 ±15% 구간만** 밝기 평균 스캔 → 3. 그 구간에서 가장 어두운 열/행 = 실제 구분선 → 4. 대비가 표준편차보다 작으면 **균일 1/3 폴백**

> ⚠️ `window_ratio`(기본 0.15)는 **1/6 미만**이어야 함(두 탐색 구간이 겹치면 엉뚱한 경계선을 줍는다 · 코드에 `assert`).

**화면 표시**

- 생성 결과는 **이미지 1장으로 표시** — 9개 셀로 쪼갠 그리드 UI 미사용
- 컷별 선택·호버·개별 액션 없음 · 확대 보기(줌)로 컷 확인
- 생성 중 로딩 상태 표시

**재생성**

- 컷별 재생성 미포함 · **재생성 단위 = 이미지 1장 전체**
- **실패 시에는 입력값 그대로 [재생성] 버튼을 1회 제공한다** — 실패 시 새로고침을 반복해야 하는 번거로움이 실사용에서 확인됨(07-27)
- **자동 재생성은 하지 않는다** — 기능적으로 가능하나 마감 시점 리스크로 판단해 의도적 미도입(07-28)
- 결과 불만족 시에는 여전히 F-01 [스토리보드 만들기] 재실행 경로 사용
- 재실행 결과가 직전 결과를 대체 · 이력 보관·되돌리기 미제공
- 재실행 횟수 제한 없음

**컷 순서 고정** — 시나리오 내러티브와 연동 · 스토리보드 내부 속성으로 캔버스(F-04)와 무관

**저장** — 생성 요청 시점에 레코드 생성(status=pending) → 완료 시 `completed`. 재생성 시 저장분 갱신(직전 결과 대체·이력 미보관)

> **수용 기준** — 1회 요청으로 3×3 9칸이 유지된 그리드 이미지 1장이 산출되고, 실패 시 유형에 따라 자동 재시도 또는 사용자 안내+재생성 버튼으로 분기한다.

### F-03 통합 프롬프트 (P0) — 영어 고정 + 1블록 + 자동 조립

**레퍼런스 이미지 분석 (파이프라인 1단계)**

- 첨부 이미지(1~10장)는 Claude가 비전 분석 — 인물 외형·의상·공간·조명·색감·스타일 특징을 텍스트로 추출
- 추출 결과를 Subject·Environment·Lighting·Style 파트에 반영해 프롬프트 조립

**프롬프트 3겹 분리 구조 (신규 명문화)** ⭐

Claude가 쓴 텍스트는 그대로 두고, **용도별로 다른 것을 앞뒤에 붙인다.**

```plain text
[Claude 원문]  ← 공유라인(로케이션; 조명/스타일; 인물 고정구) + Shot 1~9
  ├─▶ 이미지 모델로 갈 때
  │    격자 기술 지시문 + 그림체 강제문 + Claude 원문
  └─▶ 사용자에게 보여줄 통합 프롬프트로 갈 때
       Shot N + 조명/스타일 문구 + 그림체 영문 태그  ← 자기완결적으로 재조립
```

- 통합 프롬프트는 사용자가 **Seedance에 그대로 복사해 붙이는 산출물** → “3×3 격자로 그려라” 같은 이미지 생성용 지시가 섞이면 안 된다
- 재조립 시 **로케이션은 제외하고 조명/스타일만** 각 샷에 붙인다(로케이션은 컷마다 달라 전 컷 반복 시 본문과 충돌)

**출력 형식**

- 출력 영어 고정 — 한국어 입력을 시스템이 영어로 변환·생성
- 통합 프롬프트 1개 블록 — 내부에 샷별(Shot 1~9) 구분
- 영상 AI 투입 시 블록 통째 복사 · PDF Export 시에도 동일 블록 그대로 수록
- ‘더 보기’ 클릭 시 처음부터 끝까지 전체 펼침

**복사 정책** — 통합 프롬프트 전체 복사 버튼 1개만 · 컷별 개별 복사 버튼 미제공

**자동 조립**

- Seedance 6파트 순서 — Camera → Subject → Action → Environment → Lighting → Style
- [장르 프리셋 + 고급 설정값 + 시나리오] 기반 시스템 자동 조립 — 사용자의 구조 이해 불필요
- 행동 = 현재형 동사 1개·단일 동작 · 단일샷 50~70단어 가이드
- 자체 프롬프트 가이드라인 자동 삽입 — 팀 노하우(앵글/구도/품질)로 사용자 간 품질 편차 보정
- Style 파트 = 그림체 3종 고정 매핑 — 실사 → photorealistic / 3D 애니메이션 → 3D animated / 2D 애니메이션 → **japanese anime**

**글자수 제약**

- **검증 대상 = 재조립된 최종 통합 프롬프트** 합계 3000자(Seedance 2.0 입력 제약)
- 조명/스타일 문구가 9번 반복되므로 **여기서 1자는 최종 9자** → Claude 프롬프트를 건드리는 대신 조명/스타일을 **100자에서 단어 경계로 자르는** 방식으로 상한을 걸었다
- 3000자 실시간 카운터 + 백엔드 총합 검증 · 초과 시 시각적 경고 + Export 차단/경고
- 초과 시 프롬프트 생성 자동 재시도(총 3회 · §5 공통)
- 카운터는 캔버스 메모(F-04)에도 공통 노출

> **수용 기준** — 한국어 시나리오 1건으로 Shot 1~9를 포함한 통합 영문 프롬프트 1블록이 3000자 이내로 산출되고, 전체 복사가 동작한다.

### F-04 캔버스 (P0 · 병렬 트랙) — 독립된 자유 배치 보드

**정의**

- 자유 배치형 작업 보드(피그마 하위 버전) · 1인 사용 전제
- 빈 캔버스에서 시작 — 이미지·영상·메모를 직접 반입·배치하고 요소 간 관계 정리
- 생성 기능 없음(정리 전용)

**툴바 구성 (6종)**

| 툴 | 용도 |
| --- | --- |
| 선택 (Select) | 요소 선택 |
| 핸드 툴 (Hand) | 화면 이동(패닝) — **아이콘 존치**(휠 클릭 이동은 피그마·포토샵 사용자에게만 익숙한 관습이라는 판단, 07-28) |
| 미디어 삽입 (Media) | 임의 이미지/영상 반입(드래그앤드롭 다중/개별) · 영상=재생표시→클릭 재생 |
| 메모 (Memo) | 제목+내용 입력 · 드래그로 크기 지정해 생성 · 커넥터 연결 가능 · 색상 커스텀 · 3000자 카운터 공통 노출 |

**조작 규약 (v2.0 신규 명문화)**

| 입력 | 동작 |
| --- | --- |
| 스크롤 | 상하 이동 |
| `Shift` + 스크롤 | 좌우 이동 |
| `Ctrl` + 스크롤 | 확대 · 축소 |
| 휠 클릭 드래그 | 화면 이동(패닝) |

- 코어 조작 — 자유 드래그·크기 조절·회전·삭제·undo/redo · 이미지 다중 추가
- 미니맵 제공 · 기본 줌 비율 조정

**배치 · 표시 규칙 (v2.0 신규)**

- **이미지는 원본 크기로 배치** — 캔버스에 맞춰 축소하지 않는다(축소하면 너무 작아지는 케이스가 있었음)
- **메모 폰트 크기 기준 = 내보내기 그리드 이미지를 올렸을 때 읽히는 크기.** 이미지마다 크기 편차가 커 폰트를 일일이 맞추는 것은 비현실적이므로 기준점 하나를 정해 맞췄다

**첨부 상한 (v2.0 신규)** — 이미지 **10MB** · 영상 **50MB** · **캔버스당 50개**

**저장 — 자동 저장**

- **변경 발생 시마다 자동 저장** · 별도 저장 버튼 미제공(수동 저장 개념 없음)
- 대상 — 요소 추가·삭제·이동·크기·회전·커넥터·섹션·메모 제목/내용 등 보드 상태 전체
- **디바운스 1초** — 마지막 변경 후 1초 무입력 시 저장 실행
- **삭제 유예 8초** — 삭제 직후 8초간 저장을 미룬다. 그 사이 `Ctrl+Z`를 누르면 서버 저장이 아예 나가지 않아 R2 첨부파일도 지워지지 않는다
- **이탈 시 flush** — 캔버스 전환/언마운트 시 대기 중이던 마지막 편집을 즉시 저장
- **업로드 중 저장 보류** — `blob:` 미리보기가 남아 있으면 저장을 미룬다(실패 아이템은 제거해 보류가 영구화되지 않게 함)
- 저장 상태 표시 4종 — 변경사항 없음 / 저장 중… / 저장됨 / 저장 실패
- 실패 시 자동 재시도 없음 · 별도 알림창 없음 — 상태 표시로만 고지
- 이탈 직전 저장 실패는 콘솔 로그로만 기록 — 사용자 고지 미대응(**수용된 리스크**, §8)
- 저장 방식은 **전체 교체(PUT)** — 프론트가 `clientKey`로 요소를 식별해 보내면 서버가 실제 DB id로 매핑해 반환

**의존성 경계**

2. 독립 보드 — 산출물 비종속·임의 반입(스토리보드→캔버스 자동 연동 없음)
3. 역방향 쓰기 없음 — 캔버스 조작이 스토리보드 로직·컷 순서·매핑에 무영향
4. 재정렬/컷 순서 개념 없음
5. 비차단 — 건너뛰어도 생성·Export·핸드오프 성립

> **수용 기준** — 빈 보드에서 이미지·영상 반입, 배치, 커넥터 연결, 메모 작성 후 이탈·재진입 시 마지막 상태가 그대로 복원된다.

### F-05 / F-06 Export (P0) — 진입 UI 통합

**진입 UI**

- 스토리보드 상단 ‘내보내기’ 버튼 1개 → 클릭 시 형식(PDF / 이미지) 선택 후 진행
- **전용 페이지 없음** — 초기 `/export` 페이지(클라이언트 PDF 생성)는 제거되고 **백엔드 Export API 호출로 일원화**
- 흐름 — `POST .../exports/{pdf,image}` → `GET /exports/{id}` 폴링 → 다운로드 링크를 새 탭으로 열기

**F-05 PDF Export**

- 구성 — **그리드 이미지 1장 + 통합 프롬프트 전문** · 컷별 분해 레이아웃 미사용
- 이미지는 페이지 폭에 맞춰 1장 배치, 프롬프트는 그 아래 텍스트로 수록 — 팀 공유용

**F-06 이미지 Export**

- 기본 = **그리드 이미지 1장 다운로드** (원본 그대로) — 영상 AI 투입용
- **‘개별 컷 포함’ 옵션을 켜면 ZIP 생성** — 컷 9장이 함께 포함된다
    - 당초 범위 밖(“ZIP·개별 컷 파일 미제공”)으로 두었으나 배포본에는 구현되어 있다. 격자 크롭 결과물을 이미 보유하고 있어 추가 비용이 없었기 때문
    - 단, 이는 **파일 전달 편의 기능**이며 컷을 개별 객체로 다루는 기능(컷별 생성·재생성·컷별 프롬프트 복사)은 여전히 범위 밖(§8)

> **수용 기준** — 동일 스토리보드에서 PDF 1건과 이미지 1장이 각각 오류 없이 다운로드되고, ‘개별 컷 포함’ 시 ZIP에 컷 9장이 들어 있다.

### F-07 인증 / 회원가입 (P0)

- 보안 Lv2 진입 게이트 — 미인증 사용자는 스토리보드 생성·Export·캔버스 접근 불가
- 로그인 방식 2종 — ① 구글 소셜 로그인 ② 이메일 회원가입/로그인
- 이메일 회원가입 = 사내 도메인 제한 없이 오픈
- **역할(role) — **`**user**`**만 실제로 존재한다.** “관리자/일반 2종”은 기획 의도였고, **admin 가입·승격 경로는 구현되지 않았다.** 관리자 기능이 필요하면 신규 구현 대상

**인증 수단 — JWT**

- 로그인 성공 시 **access token**(메모리 보관) + **refresh token**(로그인 유지 선택에 따라 local/sessionStorage) 발급
- 모든 요청에 `Authorization: Bearer <accessToken>` (`/auth/*`, `/health` 제외)
- **인증은 선택 계층이 아니라 전제 계층** — 생성뿐 아니라 목록·단건 조회까지 토큰 없이는 동작하지 않는다
- 401 응답 시 프론트가 **자동 재발급 후 1회 재시도**(`authorizedFetch`) · refresh 로테이션 적용
- 인증 실패는 생성 실패(기술 실패·정책 거부)와 **다른 계열의 오류** — 공통 실패 처리와 분리해 안내

> **수용 기준** — 미인증 상태에서 생성·Export·캔버스 진입과 라이브러리 조회가 모두 차단되고, 2종 로그인 모두 성공 후 접근이 열린다.

### F-08 저장 / 라이브러리 — 2계층 분리

**F-08a 저장·영속 계층 (P0 · 기반)**

- F-02 생성·F-04 캔버스가 의존하는 전제 계층
- 저장 시점 2종 — 스토리보드는 **생성과 동시에 자동 저장** / 캔버스는 **변경 발생 시마다 자동 저장**
- 레코드 생성은 생성 요청 시점(`POST /storyboards` pending) · status 전이로 완료/실패 기록
- 라이브러리 노출 대상은 생성 성공 건만 — 실패·정책 거부 건은 레코드만 남기고 목록 미노출
- 소유권 — 로그인 사용자 귀속 · **모든 조회는 요청자 토큰 기준으로 스코프**
- **타 사용자 리소스 접근 시 403이 아니라 404를 반환한다** — 존재 여부 자체를 숨기기 위한 의도적 설계
- 재진입 시 마지막 저장 상태 그대로 복원

> **수용 기준** — 생성·편집 후 새로고침하거나 재로그인해도 마지막 상태가 복원되고, 타 계정에서 조회되지 않는다.

**F-08b 라이브러리 목록 UI (P1)**

- 스토리보드 전체 목록 + 캔버스 전체 목록 조회 · 사용자별 저장분 · 항목 선택 시 재진입
- 진입 UI — 헤더 버튼 클릭 → 좌측 슬라이드 사이드바(오버레이·뒷배경 흐림)

**제목 규칙 — 사용자별 순번**

- 저장 시 기본 제목 자동 부여 · **순번은 사용자별로 매긴다**(`users.storyboard_seq` / `canvas_seq` 카운터 — 전역 통산 번호 아님)
- 제목 수정 = 전용 API(`PATCH`)로 처리 · 라이브러리 목록에서 수정하며 목록·재진입 화면에 즉시 반영

**항목 관리 메뉴 — 수정·삭제 2종만**

- 목록 항목 호버 시 노출되는 ‘…’ 메뉴에서 **제목 수정 / 삭제** 두 가지만
- **삭제** — 스토리보드·캔버스 각각 삭제 가능 · 즉시 목록에서 제거 · 되돌리기·휴지통 미제공
- 스토리보드 삭제 시 `reference_images` / `generations` / `cuts`는 cascade 삭제
- **고정하기·목록에서의 내보내기 진입은 미제공**(§8)

> **수용 기준** — 목록에서 항목 선택 시 해당 작업물로 재진입되고, 제목 수정과 삭제가 목록에 즉시 반영되며, 다른 계정의 항목은 목록에 나타나지 않는다.

### 공통 — 실패 처리 · 재시도 (F-02 / F-03 공통)

**실패 2분류 — 처리 경로가 다름**

| 유형 | 예 | 처리 |
| --- | --- | --- |
| 기술 실패 | 타임아웃 · 429 · 5xx · 네트워크 | 백엔드 자동 재시도(지수 백오프 + jitter) · 소진 후 실패 확정 |
| **정책 거부 (1단계 Claude)** | 실존 인물 식별 요청 · 부적절 이미지 분석 거부 | 재시도 무의미 — 사용자 안내 |
| **정책 거부 (2단계 이미지 모델)** | 폭력·유혈 · 선정성 · 저작권 캐릭터 | 동일 — 사용자 안내 |

**백엔드 자동 재시도 4구간 (사용자에게 노출되지 않음)**

| 구간 | 트리거 | **총 시도** | 상수 |
| --- | --- | --- | --- |
| 이미지 생성 | 타임아웃 / 429 / 5xx | **3회** | `generate_image(max_retries=2)` |
| 프롬프트 생성 | 형식 불일치 / 3000자 초과 + Claude API 오류 전반 | **3회** | `MAX_ONEGRID_PROMPT_ATTEMPTS` |
| 크롭 후 R2 업로드 | 업로드 에러 | **2회** | `_CROP_UPLOAD_MAX_ATTEMPTS` |
| R2 다운로드 | 타임아웃 / 429 / 5xx | **3회** | `MAX_DOWNLOAD_RETRIES` |

> 상수마다 “재시도 횟수”와 “총 시도 횟수” 의미가 섞여 있다(`max_retries=2` = 최초 1회 + 재시도 2회 = 총 3회). 위 표는 **총 시도 횟수로 통일**. 값 조정 시 상수 이름을 먼저 확인할 것.
이미지 생성이 넉넉한 이유 — 컷별 격리가 없는 구조라 한 번 실패하면 9컷 전부 실패.
업로드 자체에는 재시도가 없음 — `upload_image_bytes()`는 실패 시 즉시 503. 위 표의 “크롭 후 R2 업로드 2회”는 크롭+업로드 묶음을 다시 도는 바깥 루프.

**재시도 원칙** — “재시도해도 소용없는 에러는 재시도하지 않는다”

```plain text
AIAdapterTimeoutError      → 재시도 O
AIAdapterUnavailableError  → 재시도 O   (429/500/502/503/504/529)
AIAdapterRequestError      → 재시도 X   (400/401 — 콘텐츠 정책 거부 포함)
```

각 SDK(OpenAI / google-genai / anthropic)의 고유 예외를 공통 타입으로 정규화해 재시도 로직이 SDK를 몰라도 되게 설계.

> ⚠️ **알려진 결함** — 위 원칙은 **이미지 생성 단계에서만** 지켜진다. 프롬프트 생성 단계는 `except (AIAdapterError, PromptValidationError)`로 잡는데 `AIAdapterRequestError`가 `AIAdapterError`의 하위 타입이라 **정책 거부(400)까지 3회 전부 재시도한다.** 결과는 틀리지 않으나(3회 실패 후 동일 안내) **Claude 호출을 3배 쓰고 대기 시간도 3배.** 액션·스릴러에서 정책 거부가 잦다는 점을 감안하면 실비용 영향이 있다. → 예외 범위를 좁히는 한 줄 수정으로 해소 가능.

**사용자 대응 경로**

- 실패 시 문구 + 실패 사유 안내 노출 · **입력값 그대로 [재생성] 버튼 1회** 제공
- 에러 메시지는 반드시 `user_facing_error_message()`를 거친다(Anthropic/OpenAI 원본 에러 텍스트가 사용자 화면에 노출되면 안 됨)
- 자동 우회·자동 재생성은 하지 않는다

> ⚠️ **알려진 한계** — 400 계열이 “콘텐츠 정책 거부”인지 “잘못 보낸 요청”인지 **구분하지 않는다.** 제공자별 에러 바디 파싱을 못 해 “시나리오 내용을 순화하거나 잠시 후 다시 시도해 주세요”라는 양쪽 다 커버되는 문구로 처리. 실사용에서 마주치는 400은 대부분 액션·스릴러 시나리오의 정책 거부다.

**사전 예방**

- 프롬프트 자동 조립 시 정책 완충 표현 적용 — 직접적 유혈·상해 묘사를 구도·정황 묘사로 치환
- 액션·스릴러 장르 프리셋에 정책 안전 가이드라인 기본 삽입(§7)

> 자체 사전 모더레이션 필터 구축은 범위 밖(§8) — 판정은 모델 응답에 의존.

> **수용 기준** — 정책 거부 시 앱이 멈추지 않고 안내와 재생성 경로가 노출된다.

## 7. 장르 프리셋 매핑

- 장르 선택 시 기본값 일괄 적용
- 액션·스릴러 프리셋에는 정책 안전 가이드라인 동반 적용
- 9컷 앵글 아크 = “설정→전개→절정→여파” 흐름에 샷 타입 매핑
- **그림체는 장르와 무관한 사용자 선택 축** — 전 장르 공통 기본값 = 실사
- **고급 설정 오버라이드 대상은 이미지 모델·그림체 2종뿐** · 톤은 프리셋 고정 · 화면비 3:2 고정 · 개별 컷 앵글 오버라이드 미제공 · 컷 순서 고정

| 장르 | 기본 톤 | 9컷 앵글 아크 (컷1 → 컷9) |
| --- | --- | --- |
| 드라마 | 따뜻함·차분 | wide → medium → close-up↑ → close → two-shot → medium → close-up → wide → medium |
| 액션 | 긴장·강렬 | extreme wide → low-angle medium → Dutch → tracking wide → close-up → high-angle → low-angle → wide → medium |
| 로맨스 | 부드러움·따뜻 | wide → medium two-shot → close-up → over-the-shoulder → close-up → soft wide → two-shot → close → medium |
| 스릴러 | 어두움·불안 | wide(여백) → high-angle → Dutch → extreme close-up → low-angle → POV-feel → high-angle → wide → close |
| 코미디 | 밝음·경쾌 | wide → medium → close-up → two-shot → wide → medium → close → high-angle → wide |

> 프리셋 정의 위치 — `backend/app/ai/prompt_adapter.py`의 `GENRE_PRESETS`. 장르 추가 시 `core/enums.py`의 `Genre`도 함께 수정.
⚠️ `prompt_adapter.py`는 “레거시(9컷 개별 생성용)” 파일이지만 현행 경로가 `GENRE_PRESETS`와 `_map_error`를 import한다 — **삭제하면 현행 생성이 즉시 깨진다.**

## 11. 미해결 · 기술 부채 (종료 시점)

> **모두 개발 기간 중 의도적으로 감수한 부채**이며, 상세 근거와 조치 방법은 **인수인계 문서 §7·§9**가 정본입니다.

### 🔴 인계 즉시 조치

| # | 항목 | 내용 |
| --- | --- | --- |
| 1 | **API 키 전량 재발급** | 레포엔 없으나 **이탈 인원 전원이 유효한 키 보유 중**(개발 기간 중 팀 내부 평문 공유). 사고 대응이 아니라 인수인계 절차의 일부 |
| 2 | **Alembic 없음** | 스키마 변경이 `main.py` lifespan에 `ALTER TABLE ... IF NOT EXISTS`로 하드코딩. 이거 없이는 스키마를 못 바꾼다 |
| 3 | **로컬 DB = 운영 DB** | 분리하지 않기로 결정(MVP 한정). 로컬 테스트가 운영 데이터에 그대로 쌓인다 |

### 🟡 인지 필요

| # | 항목 | 내용 |
| --- | --- | --- |
| 4 | 생성 경로 2개 공존 | API 기본값 `per_cut`(레거시) ≠ 실사용 `single_image`(프론트 하드코딩). API 직접 호출 시 레거시 경로를 탄다 |
| 5 | `regenerations` 미사용 모듈 | 폐지된 컷별 재생성의 잔해. 프론트에도 도달 불가 코드(`imagegrid.tsx`·`imagecell.tsx`) |
| 6 | 정책 거부도 3회 재시도 | 프롬프트 생성 단계 예외 범위가 넓음 → 호출·대기 3배(§5 공통). 한 줄 수정으로 해소 |

| 8 | Supabase 무료 플랜 | **7일 무요청 시 자동 일시정지.** 대시보드 Restore로 1~2분 복구(데이터·연결 문자열 유지) |

| 11 | 화면비 3:2 고정 | 크롭 코드가 3등분을 전제 → 화면비를 옵션으로 열려면 크롭 코드도 함께 수정 |

| 13 | 미사용 의존성 | 프론트 `@react-pdf/renderer`가 `package.json`에 잔류(`/export` 페이지 제거 후 미사용) |

## 13. 핵심 요약 — 절대 하지 말 것
